# ADR-0005: Манифест job, кеш по хешам, восстановление из SQLite

**Решение.**
- Один `manifest.json` на job (словарь stage → StageManifest), владелец — оркестратор. Перед запуском этапа его запись удаляется, после `validate()` — пишется заново.
- Cache hit = совпадение stage_version, config_hash, input_hashes, существование и sha256 выходов, `validate()`. `exists()` нигде не используется как критерий.
- Идентичность бэкендов для config_hash берётся из настроек (`services.backend_ids`), чтобы проверка кеша не грузила модели и не создавала API-клиенты.
- Очередь: задача `run-{job_id}` (детерминированный id — нет дублей). Воркер `rq.SimpleWorker`. При старте: `StartedJobRegistry.cleanup()` + `recover()` из SQLite; висящие `stage_runs.running` → `abandoned`.

**Почему.** Простой и проверяемый resume без отдельного состояния в Redis; Redis можно потерять целиком.

**Отброшено.** Манифест на каждый этап отдельным файлом (больше файлов, тот же смысл); fork-воркер RQ (проблемы на macOS); хранение прогресса в Redis.
