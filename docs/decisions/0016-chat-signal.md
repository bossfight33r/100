# ADR-0016: Сигнал чата записи стрима

**Контекст.** На записях стримов лучший индикатор момента — взрыв чата («ЖЕСТЬ», «ахахах», эмодзи). Звук стримера не всегда громкий, heatmap есть не у всех VOD.

**Решение.**
- yt-dlp помечает запись эфира (`live_status: was_live`) → `SourceInfo.was_live`.
- ingest кампании `selection: signals` для такой записи отдельным вызовом yt-dlp скачивает `live_chat` (JSON lines, `replayChatItemAction.videoOffsetTimeMsec`) и пишет `chat.json`: число сообщений (`addChatItemAction`) на каждую секунду. Это лучшее усилие: ошибка/отсутствие чата — warning, ingest успешен. Прошлый `chat.json` удаляется.
- `signals.chat_scores`: темп чата, сдвинутый раньше на 6 с (люди пишут после момента), сглаживание 6 с, превышение медианы за 120 с, нормировка по 95-му перцентилю положительных превышений. Меньше 50 сообщений на всё видео — не сигнал.
- Веса: heatmap 0,6, chat 0,5, audio 0,4 (среди доступных).
- config ingest получает ключ `chat` только для signals-кампаний: кеш остальных job не меняется.

**Отброшено / позже.** Чат Twitch (yt-dlp его не отдаёт; нужен отдельный клиент). Анализ текста чата (смех/эмодзи/ключевые слова) — следующий шаг, если темпа окажется мало. Загрузка чата длинного стрима идёт постранично и может занять минуты.
