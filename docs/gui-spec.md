# ТЗ: десктоп-приложение ClipFactory для macOS (Apple Silicon)

Скопируй этот файл целиком в чат с GPT вместе с `docs/openapi.json`. Задача GPT — **только интерфейс**. Python-ядро в репозитории уже готово и протестировано, его менять нельзя.

## 1. Что это

ClipFactory режет длинные видео на вертикальные клипы 9:16 с субтитрами. Человек смотрит клипы, одобряет или отклоняет, правит заголовки и публикует на свои аккаунты. Приложение — окно для этого процесса. Всю работу делает локальный Python-сервер, приложение только показывает данные и отправляет команды.

## 2. Платформа и стек

- macOS 14+, Apple Silicon (M1 и новее). Нативное приложение на **SwiftUI** (Swift 5.9+, Xcode 15+).
- Видео — `AVKit` (`VideoPlayer`), HTTP — `URLSession` с async/await. Сторонних зависимостей по возможности нет.
- Один Xcode-проект, структура: `Models/` (Codable по `openapi.json`), `API/` (клиент), `Backend/` (запуск сервера), `Views/`, `ViewModels/`.

## 3. Дизайн: красиво, но спокойно и удобно

Цель — приложение, которым приятно пользоваться каждый день. Не выставочный дизайн.
- Выглядит как стандартное приложение macOS: `NavigationSplitView` с боковой панелью, системные шрифты (SF), системные цвета и материалы, SF Symbols. Светлая и тёмная тема работают сами.
- Аккуратные отступы, читаемая типографика, один акцентный цвет (системный). Никаких кастомных градиентов, неонов, тяжёлых анимаций и самодельных контролов.
- Анимации только мягкие и короткие (появление списка, смена статуса).
- Пустые состояния с подсказкой («Пока нет задач — перетащи видео в окно»). Ошибки — понятным текстом и кнопкой «Повторить», не техническим дампом.
- Минимальный размер окна 900×600, адаптивная вёрстка. Доступность: подписи для VoiceOver, управление с клавиатуры.

## 4. Как приложение подключается к ядру

Приложение **само запускает** сервер и останавливает его при выходе.
1. Путь к папке проекта (где лежит `.venv`) хранится в настройках приложения (по умолчанию `~/clipfactory`; при первом запуске — выбор папки через `NSOpenPanel`).
2. Запуск: `Process` с `executableURL = <проект>/.venv/bin/cf`, аргументы `["serve", "--port", "<свободный порт>"]`, **рабочая папка = папка проекта** (там `.env` и `config/`).
3. Токен: приложение генерирует случайную строку (32+ символов, `SecureRandomCopyBytes`) и передаёт в окружении процесса как `CF_API_TOKEN`. Сам токен нигде не пишется на диск.
4. Готовность: опрашивать `GET /health` (без токена) каждые 0.5 с до 30 секунд. Не ответил — показать экран ошибки с текстом из stderr процесса (последние 20 строк) и кнопкой «Повторить».
5. Все остальные запросы: заголовок `Authorization: Bearer <токен>`.
6. Видео и обложки: `AVURLAsset` с опцией `AVURLAssetHTTPHeaderFieldsKey` (заголовок Authorization). Если не заработает — запасной вариант `?token=` в URL.
7. Процесс упал или завершился — показать баннер «Ядро остановлено» и кнопку перезапуска. Приложение никогда не слушает сеть и ходит только на `127.0.0.1`.

## 5. Экраны

Боковая панель: **Задачи**, **Поиск видео**, **Публикации**, **Отчёт**, **Настройки**.

### Задачи
- Список job (`GET /jobs`): название источника, кампания, статус (цветной бейдж), время. Обновление каждые 2 секунды, пока есть активные job; иначе реже.
- Кнопка «Новое видео»: окно выбора файла или поле для ссылки + выбор кампании (`GET /campaigns`) → `POST /jobs`. Перетаскивание файла в окно делает то же самое.
- Деталь job (`GET /jobs/{id}`): шесть этапов (ingest, transcribe, select, reframe, captions, render) с состояниями ожидает / идёт / готово / из кеша / ошибка. Для `failed` — упавший этап, текст ошибки и кнопка «Повторить» (`POST /jobs/{id}/retry`). Для активных — «Отменить» (`POST /jobs/{id}/cancel`).

### Поиск видео
- Поле ссылки на канал/плейлист + фильтры: длительность от/до (минуты), галочка «Проверить Most replayed» (медленнее), «Показывать обработанные» → `GET /discover`. Запрос может идти до минуты — показывать индикатор, не блокировать окно.
- Таблица: название, канал, просмотры (1.2M / 340K), длительность, значок 🔥 если `heatmap_points > 0`, пометка «уже было» (`already_processed`). Двойной клик — открыть ссылку в браузере.
- Выделение нескольких строк + выбор кампании → «Нарезать» (`POST /jobs` для каждой).
- Вкладка «Наблюдение»: список источников (`GET /watch`, только чтение — правятся в `config/watch.yaml`) и кнопка «Проверить сейчас» (`POST /watch/check`) с результатом по каждому каналу.

### Ревью клипов (экран job в статусе `awaiting_review`)
- Сетка карточек: обложка, длительность, оценка (score), хук, статус. Клик — открывается плеер.
- Плеер вертикальный (9:16), рядом панель: заголовок, описание, хэштеги по платформам (редактируемые), кнопки:
  - **Одобрить** (`POST .../approve`) и **Отклонить** (`POST .../reject`, с необязательной причиной);
  - **Сохранить метаданные** (`PUT .../metadata`);
  - **Субтитры заново** (`POST .../rerender-captions`);
  - **Кроп**: слайдер центра 0–100 % и «Авто» (`POST .../rerender-crop`, `center_x` от 0 до 1, `null` — авто).
- После перерендера job возвращается в обработку и сам вернётся в `awaiting_review`; клип сбрасывается в `pending_review`. Показать это явно («Пересчитывается…») и опрашивать статус.
- Если у job есть сигналы (`GET /jobs/{id}/signals` отдаёт 200; кампании `selection: signals`/`hybrid`): над сеткой — график на **Swift Charts**: линии рядов `trace.series` (звук, чат, heatmap; шаг `trace.hop` секунд) и жирная линия `trace.fused`, клипы — полупрозрачные полосы `start…end` с подписью id. Клик по полосе — открыть клип. 404 — график не показывать.
- Горячие клавиши: ←/→ между клипами, пробел — пауза, ⌘↩ — одобрить, ⌘⌫ — отклонить.

### Публикации
- Кнопка «Запланировать и опубликовать» на экране job (`POST /jobs/{id}/publish`; с `schedule_only=true` — только расписание). Показать результат: для каждого аккаунта время (в часовом поясе аккаунта из `GET /accounts`) и статус.
- Список всех публикаций (`GET /publications`). TikTok и Instagram дают статус `exported` и путь к папке-пакету — кнопка «Показать в Finder». Для них — ввод просмотров вручную (`POST /publications/{id}/stats`).

### Отчёт
- `GET /report`: общий доход и просмотры, таблицы по кампаниям и аккаунтам, топ клипов, эффективность типов хуков. Простые таблицы и пара графиков на **Swift Charts**.

### Настройки
Папка проекта, порт (авто), статус ядра, версия (`/health`), возможности машины (`GET /capabilities`: ffmpeg, рабочие энкодеры). Ключи API и токены здесь **не хранятся и не редактируются** — они в `.env` проекта.

## 6. API

Полная схема — `docs/openapi.json` (OpenAPI 3). Ошибки — JSON `{"detail": "текст"}` с кодами: 401 нет или неверный токен, 404 нет такого, 409 конфликт состояния (например job уже идёт), 400 неверный запрос, 422 неверный формат. Показывай `detail` пользователю как есть, он читаемый.

Статусы job: `queued, ingesting, transcribing, selecting, reframing, captioning, rendering, awaiting_review, scheduled, publishing, published, failed`. Статусы клипа: `pending_review, approved, rejected`. Статусы публикации: `scheduled, publishing, published, exported, failed`. Время во всех ответах — ISO-8601 UTC.

Запросы на постановку (`POST /jobs`, `retry`, `rerender-*`) возвращают 202 сразу, работа идёт в фоне: **опрашивай** `GET /jobs/{id}`.

## 7. Безопасность и запреты

- **Не изменять** ничего в `src/`, `tests/`, `docs/` (кроме нового). Только новый Xcode-проект (например, в папке `desktop/`).
- Токен только в памяти и в окружении дочернего процесса; не логировать, не показывать в UI, не писать в `UserDefaults`.
- Не отправлять запросы никуда, кроме `127.0.0.1`. Никаких аналитик и обновлений из интернета.
- Не пытаться запускать ffmpeg, Whisper или читать базу — всё только через API.
- App Sandbox включать не обязательно в первой версии (нужен запуск `.venv/bin/cf` и доступ к папке проекта).

## 8. Что не входит в первую версию

Упаковка Python внутрь `.app`, автообновления, нотаризация, TikTok/Instagram-API, редактор таймлайна.

## 9. Критерии приёмки

1. Проект собирается в Xcode без предупреждений, запускается на M1.
2. Запуск без работающего сервера: приложение само поднимает `cf serve` и показывает пустой список задач; закрытие приложения останавливает процесс.
3. Перетащил видео → job прошла этапы → клипы появились в сетке, видео воспроизводится с перемоткой.
4. Одобрить, отклонить, править заголовок, перерендерить кроп — всё отражается в списке без ручного обновления.
5. Падение job показывает упавший этап и работающую кнопку «Повторить».
6. Поиск видео: ссылка на канал → таблица по просмотрам → выбор двух строк и кампании → две job в списке задач. Для job игровой кампании виден график сигналов с полосами клипов.
6. Светлая и тёмная тема выглядят нормально; окно ресайзится без поломок.
7. При неверном токене или остановленном ядре — понятное сообщение, а не краш.

Для проверки без реальных ключей в `.env` проекта поставь: `CF_TRANSCRIBER=fake CF_LLM_PROVIDER=fake CF_FACE_DETECTOR=fake` — pipeline пройдёт на заглушках и выдаст настоящие клипы.
